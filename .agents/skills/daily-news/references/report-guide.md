# 报告与来源记录

以今日新闻为入口，结合近一个月的新闻，回答“如何发展到今天、为什么此时发生、接下来可能如何变化”。先核查再下结论，避免仅转发新闻或用历史选题列表代替背景研究。

## 如何使用近月新闻

默认研究窗口为报告日期前30个自然日至昨天，今日新闻单独作为最新进展；用户指定其他窗口时按其要求。先读摘要模式的 `history[].news` 和新闻元数据，再用 `context --history-detail full` 分页读取相关历史报告及 `history[].research`，寻找线索与原始链接；按 `history_page.next_offset` 继续，昨天的正文通过 `report_ref` 引用顶层 `yesterday_report`。过去未被选入报告的新闻、只有新闻没有报告的日期也属于研究材料。

根据今日事件，定向补查近月的政策变化、关键数据、企业行动、市场反馈与各方回应。用事件发生日期串联前因后果，保留与理解今天有关的节点；发布日期不能冒充发生日期。能够取得时使用2–4个关键节点即可，不必逐日罗列。与今日事件没有可验证联系时说明未发现充分关联，不为凑满一个月而拼接新闻。关键前因早于窗口时可简要追溯，标明它是更早背景。

历史报告中的推断、预测和来源不自动视为事实。沿原始来源复核关键节点，检验后续新闻是否支持、削弱或推翻原判断；指出判断发生变化的证据。区分“同一主题”“时间上先后发生”与“有依据的因果关系”，也考虑能解释现象的其他原因。

`history_coverage` 只说明本地存档覆盖，不保证相关新闻齐全。若本地不足30天或缺少关键背景，按需搜索补齐；仍有缺口时在正文或来源记录中说明实际覆盖、未核实环节及其对判断的限制。不要声称已完整分析近月新闻。

## 分析与正文

每个重点事件围绕以下问题展开，标题和篇幅按材料调整：

- **今日增量**：今天新发生、确认或改变了什么，与昨日相比有何实质变化。
- **近月脉络**：用带日期、带来源的关键节点说明事件如何演进到今天，以及今天处于哪个阶段。
- **驱动逻辑**：解释触发因素、主体动机、约束条件与影响传导路径，给出证据；区分短期触发与较长期的结构性因素。政策关注出台背景、影响链和受益/受损方；产业关注市场格局、资本和竞争；科技关注技术路线与产业化；社会事件关注结构性问题和历史可比案例。
- **后续发展**：结合已有脉络说明可能的下一步及二阶影响，列出未来1–3周可观察的数据、行动或时间节点，并说明什么证据会支持或推翻判断。预测写明成立条件和不确定性，不把趋势外推当作确定事实。

同一主题的重要新进展、转折或反证可以继续作为重点；重复报道或没有实质变化时才减少篇幅。衡量标准是今天的信息增量及其对既有判断的影响。

报告通常包含：

- 今日关键事件：每条2–3行，点明今日增量及其重要性。
- 深度分析：逐条写今日增量、近月脉络、事实核查、驱动逻辑与后续观察。
- 跨事件关联：明确区分事实联系与分析推断。
- 值得警惕的信号：1–2个有依据的风险点。
- 参考来源：关键说法就近引用，列出查询过的原始URL、来源标题和已知的发布日期。

正文用简洁中文，标题使用文字，不用 emoji 作为装饰或栏目标记。区分已证实事实、推断和预测。不要把旧数据当成当天的新进展，也不要把两个转载同一稿件的网站视为两个独立来源。避免复制大段来源正文。

## 来源记录

今日事实与历史节点都要就近引用支持该说法的原始来源，不只引用当天报道或过去的自写报告。来源记录涵盖用于分析的历史来源；已知事件发生日期可补充 `event_date`，发布日期未知时留空或省略，不编造。

来源记录使用以下 JSON 格式，由 `save-report` 写入 SQLite，供复查；输入文件按 Skill 的“中间产物管理”规则临时创建并清理。字段按实际可取得的信息填写，缺失数据不编造：

```json
{
  "sources": [
    {
      "title": "来源标题",
      "url": "https://example.com/original-release",
      "published_at": "YYYY-MM-DD",
      "event_date": "YYYY-MM-DD",
      "checked_at": "YYYY-MM-DD",
      "claim": "该来源支持的关键事实",
      "notes": "原始发布、与其他来源一致或存在冲突"
    }
  ],
  "limitations": ["尚无法独立核实的内容"]
}
```

每次修改正文时同步提供来源 JSON。正文发生变化但省略来源时，工具会清空旧来源，避免新报告沿用旧报告的核查资料；正文不变且未提供来源时保留已有记录。

工具只保存这些资料，不访问来源URL或判断事实是否正确。Agent 对来源核查、引用和结论负责。不把模型内部推理、密码或API密钥保存到来源记录。
